## 1. 项目独立解释器与环境

以下 uv 命令已在本服务器执行。Python3.11.16 安装在 `.tools/python/cpython-3.11.16-linux-x86_64-gnu`；`.venv-cpu` / `.venv-gpu` 均基于该项目内解释器，后者目前仅作候选解析环境，不代表 GPU 软件安装完毕。

```bash
UV_CACHE_DIR="$PWD/.cache/uv" UV_PYTHON_INSTALL_DIR="$PWD/.tools/python" uv python install 3.11 --no-bin
UV_CACHE_DIR="$PWD/.cache/uv" UV_PYTHON_INSTALL_DIR="$PWD/.tools/python" uv venv --managed-python --python 3.11 .venv-cpu
UV_CACHE_DIR="$PWD/.cache/uv" UV_PYTHON_INSTALL_DIR="$PWD/.tools/python" uv venv --managed-python --python 3.11 .venv-gpu
.venv-cpu/bin/python -c 'import sys; print(sys.executable); print(sys.base_prefix)'
```

本次 `.venv-cpu` 原先基于用户共享 uv 解释器，收到独立环境要求后，用同一 uv 命令加 `--clear` 重建为空环境。此过程只清理本轮创建的环境；新会话不得对已有训练环境直接 `--clear`。旧测试不作为本轮最终验证，最终已在项目独立解释器重跑。没有使用系统 Toolkit 执行测试。

沙箱内首次 Python 下载网络失败，已使用获准网络路径下载成功；具体版本/来源与结果记录在日志和 PROGRESS。CPU 工具不需第三方 Python 包，直接执行源码即可。不要将根目录 `.git` 的存在误认为 Git 初始化成功；当前为空的只读目录，`git rev-parse` / `status` 均失败，代码通过源文件 SHA256 留痕，不伪造 commit。

## 3. 候选依赖与静态接口

官方来源见 [依赖审计](../dependency-audit.md)，安装流程见 [requirements/README](../../requirements/README.md)。固定待验候选为 Python3.11、verl0.6.1（commit `d62da4950573d7a4b7ef2362337952e7ab59e78d`）、Torch2.7.1/cu126、vLLM0.10.0/cu126、Transformers4.53.2。`configs/s0.json` 是规划校验文件，不是 verl 训练配置。

本轮先实际执行了禁止任何源码构建的解析：

```bash

```

结果在 `dependencies/resolve.log`：verl 固定 commit 已拉取，但动态元数据需要构建，命令被 `--no-build` 阻止；这不是依赖不兼容结论。已检查该 commit 的 `setup.py` / `pyproject.toml`：setuptools 纯 Python 元数据，无 CUDA 编译。审阅后的受控解析允许 verl 与纯 Python pylatexenc 构建元数据，其他包只取二进制：


实际结果：官方 vLLM wheel 不支持该次 Range 请求，转为完整流式下载；数分钟未生成完整解析结果后，本次限时预检已中断（退出130）。证据见 `dependencies/resolve-reviewed.log`、`preflight-interruption.json`、`result.json`。这不是兼容性失败；尚未生成 resolved-candidate、尚未安装 GPU 包、尚未生成 lock。后续应单独安排完整下载/解析，记录时长与本地哈希。解析产物即便生成，也只是 `resolved-candidate`，没有安装、导入与 GPU 证据时不宣称通过。

## 常见失败与恢复

- `ModuleNotFoundError: procure_rl`：从项目根目录执行，带 `PYTHONPATH=src`。
- 输出目录存在：换新目录，避免覆写日志；S0 无 checkpoint，直接新 run 重跑。
- uv 缓存写到只读 home：每条 uv 命令指定项目 `UV_CACHE_DIR` / `UV_PYTHON_INSTALL_DIR`。
- NVML 返回权限错误：保留失败报告，检查当前执行上下文；只读主机查询与计算授权分开。不能因为沙箱看不到 GPU 就写主机没有 GPU。
- `nvcc` 不在 PATH：只列系统路径，不执行系统工具，不据此安装/升级系统 CUDA。需要编译时在项目内建立独立 Toolkit。
- `Building source distributions ... disabled`：检查固定源码构建配置后记录允许范围；不擅自放开所有 CUDA 扩展源码构建。
- 网络、依赖解析失败：分别保存网络报错和 resolver 报错，不混称为 GPU 不兼容，不自动换框架。
