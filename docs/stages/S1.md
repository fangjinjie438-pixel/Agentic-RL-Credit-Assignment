## 范围与固定来源

EComAgentBench 固定 commit `97eff345811fdf652a2135d38d874f2932e11702`，原样 75 文件及逐文件哈希在 `third_party/ecomagentbench/<commit>/UPSTREAM-MANIFEST.json`。代码 MIT 与数据研究用途条款分别保留，准确接口、许可及官方评分差异见 [上游审计](../ecom-upstream-audit.md)。本项目不修改上游源码：适配器核验所加载 11 文件的固定哈希，仅用项目子类把连接替换为只读 SQLite。

实际执行九个上游工具的 SQL/FTS5、过滤、详情、评论、统计、店铺、画像、确定性澄清与推荐；不注册 `python_execute`。项目新增 `reset/step/snapshot/restore`、总步数、显式证据、过程事件和独立终局验证器。S1 不导入原生依赖 LLM 的 `ShoppingAgent` 或 judge。

固定 [fixtures/s1](../../fixtures/s1/README.md) revision `s1-fixture-v1`：9 个虚构办公扩展坞、45 条结构化证据、2 个英文工程任务、7 个待判定候选。train 中有两个合法解及单约束反例；dev 有预算与接口反例。`sealed_test/official_test` 中的两个虚构商品只用于隔离检查，与真实官方目标和 S2 封存集无关。规格真值独立于验证器列出，由协作 agent 编写并逐项核对；本轮没有额外人工签核。

官方 662 条任务仅核对记录数和状态元数据，没有用目标或 rubric 调整奖励、生成工程任务或挑选商品。约 26.9 GB 官方数据库与原生 LLM judge 未下载/运行；本次不产生官方评测分数。

## 输入、接口与可见性

代码调用链：CLI → `env.smoke` → `catalog.build_catalog/load_tasks` → `ProcurementEnv` → `NativeEComTools` → 独立验证器。各文件输入输出见 [env README](../../src/procure_rl/env/README.md)。

`build_catalog` 从固定 JSON 在新目录生成 `train/dev/sealed_test/official_test.sqlite` 和内容哈希清单；各 split 是物理独立文件。运行时核验哈希，以 `mode=ro&immutable=1` 与 `query_only` 打开，无数据库或 WAL 写入。会话任务与 Catalog 必须属于相同 split。

- `reset(seed=0)` 仅返回 query、已公开的 query 约束、预算和协议版本。
- `schemas()` 返回九个原生 OpenAI function schema；推荐工具新增可选 `checks`（逐约束证据引用）。原生 `product_id/reasoning` 保留。
- `step({"name": ..., "arguments": {...}})` 或同结构 JSON 字符串返回 `StepResult`。只有 `observation` 可送入 Agent；事件、奖励、私有事实、完整任务与终局报告是审计数据。
- `snapshot()` 保存任务/商品库/策略哈希、澄清状态、首次覆盖集、历史、剩余步数和 RNG；`restore(snapshot)` 先在独立候选会话真实重放并比对完整状态，再替换原会话。损坏、篡改或跨配置恢复拒绝。
- `trajectory()` 输出逐步动作与 observation、`step_rewards/verifier_events/policy_version`。S1 尚无 tokenizer，`turn_spans=[]` 并显式标记未 token 化，不能当作 S3 token 对齐验收。
- `close()` 释放该会话只读连接。多个会话可并发共享 Catalog，但不共享澄清、奖励或历史状态。

隐藏约束只有画像或相应澄清工具返回后才公开；review 专属供电事实只有真实评论 FTS 返回对应原句后才附带可引用证据。Agent 自称已核验或给出关键词不生成证据。

## 计分与预算

终局 `success/terminal_reward` 严守 PLAN baseline：有效推荐满足全部硬约束且未超过总预算为 1，否则为 0。`delivery_success` 额外要求需求已揭示、每项 checks 完整，引用已访问且绑定当前商品/字段的合法证据。猜中合法商品但未收集证据可获得事实分 1，同时交付诊断失败；不把缺证据混入 baseline 奖励。

过程事件来自真实 observation。隐藏约束首次覆盖总正预算 0.4、相关约束证据首次覆盖总正预算 0.6；证据可支持或排除候选，同一约束换候选不能刷新奖励。无效动作扣 0.05，完全重复且无新增信息扣 0.02。语义近似但不同参数的无进展调用不保证识别为重复，仍不能刷新正奖励预算。

默认 40 个尝试动作，加载器支持 1–80（较小值只作边界测试），非法 JSON/未知工具也消耗总步数。第 40 次可正常推荐；第 40 次仍未推荐则终局预算失败。澄清最多 10 次，超过 100 字符的原生拒绝也消耗澄清次数并记无效。终局后不能继续 `step`；离线修复可恢复终局前快照，快照不进入在线 Agent 的工具列表。

## 恢复、排错与交接

没有模型 checkpoint。本阶段数据库损坏时保留失败目录，按固定 JSON 在新目录重建；源哈希失败时恢复固定 commit，禁止自动替换成最新 main。非空 WAL/journal 表示输入未完成提交/checkpoint，应由构建流程处理后再打开，不能忽略校验。

`ModuleNotFoundError` 先检查项目根目录与 `PYTHONPATH=src`；缺 FTS5 会真实报错，不能以空结果替代。畸形或过深 JSON、非有限值、重复键、布尔页码、过大整数页码和未知字段均作为无效尝试记录。数据库 I/O 错误向外传播并让 run 失败，避免把基础设施错误计成 Agent 失误。快照重放不符时保留快照和轨迹，检查 task/catalog/policy hash，不绕过比较。
